#1093 check: windows opened after Direct3D 12 falls back to OpenGL in the same run
Built from main at 5032e73a6 (release), on Windows 11 x64 with an NVIDIA GeForce RTX 4060
(OpenGL 3.3.0 NVIDIA 610.88). Each run had its own test copy: its own data folder and
download folder, a lab server on 127.0.0.1, windows opened with /show (addurl, options,
progress for a running 2 GB download), captured with tools/lab/cap-own.ps1 (PrintWindow).
"drawn" = the client area has more than one colour; "capture N" = the capture it took,
taken every 500 ms, the first 1.5 s after the window appeared.

Failure paths:
- direct3d-none: Direct3D 12 finds no adapter (MDM_RENDERER=direct3d-none, off-screen copies).
- pipeline: Direct3D 12 starts its device, then egui's pipeline fails ("The egui renderer
  couldn't be created: Validation Error"), as in the 32-bit build. On x64 it was forced with a
  local, uncommitted probe (an invalid sample count for the Direct3D try only); the 32-bit build
  fails there by itself with MDM_RENDERER=direct3d.
